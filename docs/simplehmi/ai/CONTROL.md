# 可视化驱动的规则与步骤流程控制（开发中）

智能控制支持阈值回差规则与可配置步骤流程。它复用 FUXA 读写链路，支持模拟点位及 Modbus TCP 点位；不是通用 PLC 编程环境，也不能替代现场安全联锁。

## 可操作入口

- 编辑器次级工具栏的 **控制**、运行页的 **自动控制** 打开同一个面板，不增加一级导航。
- 添加/编辑/删除规则先产生 Agent 变更计划，展示关联影响后应用。规则配置变化会退出自动控制，保存不等于启动。
- **启动自动控制** 只对当前进程、当前工程控制配置有效。重启、切换工程、设备/变量/规则/模式变化后需重新检查并启动；只移动画面组件不会中断规则。
- **人工接管** 立即阻止后续自动写入；已发出的写入仍完成回读与记录，不会被假装撤销。此按钮不负责把设备输出改为零。直接手动写受控点位也会暂停规则，随后执行人工写值。
- 真实设备输出需在面板勾选本次会话明确列出的点位，后台对完整目标列表做校验。当前权限边界仍是本机接口，尚未接入多用户身份、细粒度 Agent 角色或远程授权。

## 规则模型

`project.control.rules` 是持久化配置，每条规则包含：

| 字段 | 含义 |
|---|---|
| id / name / enabled | 全工程唯一标识、中文名称、是否参与控制 |
| inputTag / outputTag | 输入和可写输出；同一输出只能由一个启用规则或流程控制 |
| direction | low：低于启动阈值开启、高于停止阈值关闭；high 相反 |
| onThreshold / offThreshold | 有效回差区间；区间内保持已确认的输出状态 |
| onValue / offValue | 两个明确的输出值 |
| outputMin / outputMax | 输出允许范围，还必须满足点位类型及倍率范围 |
| holdMs | 触发条件持续多久后动作，0–60000 ms |
| minIntervalMs | 两次自动写入最小间隔，1000–3600000 ms |
| maxAgeMs | 输入、输出及允许条件的最长数据年龄，500–60000 ms |
| guards | 全部满足才允许开启的条件，最多16项；比较符 lt/lte/gt/gte/eq/ne |

数据新鲜但允许条件不满足时请求关闭，略过稳定时间，仍遵守写入间隔。数据失效、输出被其他来源改写、驱动拒绝或回读失败时，执行器中止自动写入，保留异常记录并提示人工确认当前设备状态，不猜测停机是否成功。

自动控制每 500 ms 评估，实际读写还受设备轮询、规则稳定时间、写入间隔和回读耗时影响。阈值触发不等于连续时间下精确停在该液位，不应把界面规则用作硬实时安全控制。

删除规则引用的变量会自动禁用该规则并留下原因，关联影响在预览中可见。恢复完整点位后需重新检查、启用及启动。

## API 与 Agent

- Agent 操作包含 `rule.upsert {rule}` / `rule.delete {id}` 与 `machine.upsert {machine}` / `machine.delete {id}`；工程 JSON Schema 与模型提示包含完整定义。
- `GET /simplehmi/api/control/status`：当前人工/自动/故障状态、规则状态、`machines` 步骤状态、已验证写入次数及最近记录。
- `GET /simplehmi/api/control/events`：最近200条本机控制记录。
- `POST /simplehmi/api/control/arm {expectedRevision, allowPhysical?, physicalTargets?}`：明确启动。工程版本必须匹配；真实输出需要 allowPhysical=true 且 physicalTargets 与所有实际目标一致。授权不持久化。
- `POST /simplehmi/api/control/pause {}`：人工接管。
- `/values` 增加 control 状态摘要，运行页持续显示状态。

控制日志在用户工程目录的 `control/events.jsonl`，记录启动、请求写入、回读、故障、人工接管。2 MB 后保留一份上一代文件。当前不是防篡改审计存储，不能宣称满足工业合规留存要求。

## 双水箱演示

AI 工作台选择“智能控制”再生成示例，或导入 `examples/water-control.simplehmi.json`。水量守恒模型保持不变，新增规则：高位水箱 ≤ 35% 时启泵，≥ 40% 停泵，源箱必须 > 5%。泵初始停止，点击启动自动控制后才执行。

浏览器验收把阈值改为 31% / 32%，实际完成两次已回读写入：初始30%开启，在32.33%时触发关闭（包含稳定等待和采样间隔），总水量保持4.15m³；随后人工接管，未再次自动写入。

## 步骤流程

在“控制 → 添加步骤流程”配置名称、起始步骤、各步骤的目标输出和跳转条件。高级运行参数与输出范围默认折叠。点击“检查步骤流程”先验证，再“应用控制修改”；继续修改表单会使旧预览不可应用。保存后保持人工接管，点击“启动自动控制”才执行。当前步骤以黑色显示，旁边显示已验证写入次数。

`project.control.machines` 可选，旧工程兼容。每个流程最多 30 个步骤、16 个输出，每工程最多 20 个流程。

| 字段 | 含义 |
|---|---|
| id / name / enabled | 全工程唯一标识、名称、是否参与控制 |
| initialState | 起始步骤 ID；重新启动总是从这里开始，不自动恢复历史动作 |
| maxAgeMs / minIntervalMs | 所有引用的数据时效、两次步骤切换的最小间隔 |
| guards | 持续运行允许条件；全部满足才可运行，失效中止后续写入 |
| evidence | 可选知识条目 ID 与版本；版本变更或过期停用流程 |
| states[].id / name | 流程内唯一的步骤标识及名称 |
| states[].timeoutMs | 最长停留时间；0 不限制，其余为 1000–86400000 ms |
| states[].actions | 全部受控输出的目标值 `{tagId,value,min,max}`，每步各声明一次 |
| states[].transitions | 跳转 `{to,priority,afterMs,holdMs,conditions}` |

同一步骤跳转优先级不能重复，数字越小优先级越高。进入步骤达到 `afterMs` 后，全部条件保持 `holdMs` 才可切换，仍需满足最小切换间隔。没有条件的跳转必须至少延时 1000 ms。所有步骤需能从起始步骤到达；可配置分支、循环，或无跳转的终点。终点继续监测输出和数据，直到人工接管。

启动时，实际输出必须与起始步骤一致。系统不会为进入起始步骤先强制写值。进入下一步时按动作顺序逐点写入并回读，已处于目标值的点跳过。全部成功才标记步骤切换完成。每次写入前重新检查数据、允许条件和非输出触发条件；本流程输出作为触发条件时使用切换开始时的观察值，避免自己的前一项动作取消同一次跳转。

多个设备输出不构成原子事务。第二项失败时，第一项可能已执行；事件记录保留成功回读，流程中止并提示核对，不自动回滚设备。切换中人工接管阻止剩余动作，已发出的指令仍完成回读记录。超时也只停止后续自动写入，不猜测安全输出。需要现场安全停机时，由 PLC 联锁等独立机制保障。

删除引用变量或修改知识版本会停用依赖流程，预览展示原因；补回数据后也不会擅自重新启用。所有启用规则和流程共享输出归属检查，同一点不能被两个控制器同时接管。尚不支持多流程事务、并行步骤或 PLC 编程语言兼容。

### 可导入的三步供水演示

导入 `examples/water-steps.simplehmi.json`，打开“控制”启动：待机 2 秒 → 开泵供水 → 高位液位达到 32% 后停泵。起始输出为 0，守恒水量 4.15 m³。供水步骤 30 秒超时；数值只是演示，不是现场设定。完成后要再次运行，需重新导入模板恢复模拟初始条件，或自行调整经核对的控制条件。
