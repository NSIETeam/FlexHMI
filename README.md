# FlexHMI 0.3.0

基于 **frangoteam/FUXA v1.3.4** 的中文极简工控组态工作台。拖入组件、绑定变量、运行。内置守恒双水箱供水和垃圾焚烧发电演示工程，不连接 PLC 也能完整体验。

本项目是可以启动、保存工程和读取/写入 Modbus 的功能 MVP。FUXA 的协议驱动、设备状态机、内部变量、数据采集及完整工程师编辑器全部保留。

## 工控机预览版与 AI 工作台

产品现名 **FlexHMI**。原 `/simplehmi/` 地址、工程格式与目录继续兼容。新工控机版复用已安装的 Microsoft Edge，内置 Node.js 与完整通讯依赖，提供编辑、运行、全屏与停止服务入口，见 [工控机版说明](docs/simplehmi/IPC-EDITION.md)。Windows x64 / ARM64 安装包为未签名预览版。旧交叉构建安装器启动时崩溃；使用匹配的 Windows 工具链重建安装器后，双架构自动验收已通过。重建包仍使用 0.3.0 旧载荷，不包含此后新增的 MCP 与连接编辑功能，尚未作为正式版本发布。

AI 工作台支持三种模式、生成计划、引用知识评估、关联影响预览与规则配置。已有真实外部 Agent 评估应用证据；内置模型需在界面配置自己的服务，尚未用真实账号验收。行业数据库能力和验收边界见 [行业评估](docs/simplehmi/ai/INDUSTRY.md)。

## 历史 0.2.0 桌面版与图形扩展

提供 Windows x64 / ARM64 两种安装包，内置运行环境。安装、架构与验收边界见 [发布说明](docs/simplehmi/RELEASE-0.2.0.md)，完整产品批判见 [审查记录](docs/simplehmi/PRODUCT-REVIEW.md)。当前未签名，尚未完成 Windows 实机安装回归。

## 立即启动

从 GitHub 首次获取源码后，安装后端依赖并启动（需要 Node.js 22 或更高版本）：

```sh
git clone https://github.com/NSIETeam/FlexHMI.git
cd FlexHMI
npm ci --prefix server
npm start
```

仓库已公开，可直接克隆；基于 FUXA 的衍生项目，保留原有 MIT 许可和版权声明。已经安装过依赖的本地目录，直接运行 `npm start`。预编译工程师界面包含在仓库内，普通启动不需要安装 Angular 开发依赖。

打开 **http://127.0.0.1:1881/simplehmi/**。macOS 也可以双击 **Start-SimpleHMI.command**，启动就绪后自动打开浏览器。首次启动默认显示带实时模拟数据的守恒双水箱供水工程。

从演示包解压后启动：

```sh
# 推荐 Node.js 22 LTS；本次在 macOS arm64 / Node.js 24.20.0 上验证
./start-simplehmi.sh
```

脚本会安装 server 依赖；包内已包含编译完成的 `client/dist/`，无需再次构建 Angular。首次安装需要网络。Windows 可在项目目录运行 `npm ci --prefix server` 后 `npm start`。

其他命令：

```sh
npm run setup      # 安装服务端和 Angular 开发依赖
npm run check      # 检查 SimpleHMI 源码语法和演示数据
npm run build      # 检查并重新构建原 FUXA 工程师前端
npm run build --prefix server  # 原服务端 TypeScript 构建
npm test           # 隔离端口与数据目录的集成验收
PORT=1885 npm start # 换端口
npm run modbus:sim # 启动真实 Modbus TCP 协议测试从站，127.0.0.1:1502
```

`npm test` 使用 1882/1503 端口，不修改交互演示工程。若端口占用先关闭对应测试实例。

## 三分钟体验

### 垃圾焚烧发电流程演示

**项目 → 垃圾焚烧发电 · 流程演示 → 运行 → 启动流程**。

按照用户参考图重建，包含垃圾车、垃圾池与抓斗吊车、焚烧炉、余热锅炉、汽轮发电机、半干式反应塔、布袋除尘器、引风机、烟囱；保留二次风/空气预热、烟气再循环/再循环预热、石灰浆、活性炭、底灰与飞灰支路。共 17 个设备节点、25 个变量、2 个页面（工艺全流程 / 趋势与报警）。

- 启动后模拟上料、升温、蒸汽和发电，管道显示流向，设备状态和参数同步变化。
- 点击设备查看说明和当前参数快照。点击“趋势与报警”查看实时曲线及本次服务运行的历史缓存。
- 点击“模拟炉温报警”，炉温升高，超过演示阈值 950 °C 后显示报警；点击“复位演示报警”观察回落与解除。
- 点击“停止流程”观察温度、压力和功率逐步回落。上述过程为加速模拟，不能用于推导真实设备启停时序。
- 返回编辑可选中设备、数值和按钮修改布局、属性与绑定；流程专用连接线目前由 JSON 路径定义，不提供可视化管线布线工具。
- 工程自动保存；可从项目菜单导出，也可导入 `examples/waste-to-energy.simplehmi.json`。重新打开内置模板会恢复模板布局；需要保留自定义修改时从本地工程列表打开，或先导出备份。

设备图元为可编辑的原生 SVG，未将参考图片铺成静态背景。`simplehmi/process.js` 负责设备、流向和状态显示，`server/simplehmi/waste-simulation.js` 计算模拟过程，数据依然经 FUXA 的内部 Device/Tag 运行链路进入画面。`simulation: "waste-to-energy"` 启用该模型。

**边界：** 本演示未连接现场 PLC，不包含真实焚烧炉控制程序、联锁、安全停机、排放合规判断或工业热力模型。4.4 MPa / 450 °C 为参考图中的演示目标，其他模拟数值也不是现场设定。接入真机时移除工程中的 `simulation` 字段，按下文添加 Modbus 设备和点位，再将组件绑定到已核对的实际读数；演示用 `plant_run` / `temperature_fault` 按钮不可直接映射为真实整厂启停或故障命令。

### 从空白工程开始

1. 首屏可直接查看守恒双水箱供水示例，数值来自 FUXA 内部变量，每秒更新。
2. **项目 → 新建工程**，填写名称。
3. **设备 → 添加设备 → 模拟设备**，测试连接后添加。添加一个“温度”变量，选择自动波动、初始值 23.6、单位 °C。
4. 从“组件”拖一个数值到画布，选中它，在右侧 **数据 → 绑定变量** 选择温度。或者从 **设备变量** 直接拖温度进画布，选择 **数值 / 仪表 / 实时曲线** 自动绑定。
5. 拖动组件移动，拖右下角调整大小，在“外观”修改文字、颜色、坐标和尺寸。
6. 点击 **运行**。编辑器三栏消失，数值继续实时变化。
7. 所有画面修改自动保存到本机服务。刷新、重启服务或从“项目”打开已保存工程即可恢复。项目菜单也支持 JSON 导入和导出。

按钮写值：变量配置勾选“允许按钮 / 开关写入这个变量”。模拟变量会使用手动值模式。拖一个按钮或开关，绑定该变量，在“动作”选择“切换 0 / 1”或“写入指定数值”，进入运行模式后点击。成功提示要求驱动确认写入且收到更新的回读值。

| 额外显示方式 | 变量拖入时支持仪表 |

## 架构与复用边界

```text
浏览器：/simplehmi/                 工程师：/editor /device /plugins /view
中文 HTML / CSS / JavaScript       原 FUXA Angular 18 编辑器
           │                              │
           ▼                              ▼
SimpleHMI 产品适配 API ───────→ FUXA Express / Runtime
工程 JSON、布局、向导            project.setProject + runtime.restart
质量判断、回读验证               devices.getDevicesValues / setTagValue
           │                              │
           ├─ 模拟值 → FuxaServer 内部变量  │
           └──────────────────────────────┤
                                          ▼
                              原 Device 状态机与 Modbus 驱动
                                          │
                                          ▼
                                      PLC / 测试从站
```

**没有重写 Modbus 协议。**通信调用原 `server/runtime/devices/modbus/index.js`，底层库为固定版本 `modbus-serial@8.0.23`。设备和变量转换为原生 Device/Tag，工程师设备页可以看到同步的 Modbus 设备。

普通画面采用轻量 DOM/SVG 渲染器，以尽快实现三栏体验；没有复制或重写 Angular 大型编辑器。**SimpleHMI 布局目前不能与原 FUXA SVG 画面双向转换**，两个编辑器共享通信 Runtime，画面格式独立。原 FUXA `/view` 只渲染原生 FUXA 画面；SimpleHMI 画面使用自己的运行地址。

工程布局独立存储在 `server/_appdata/simplehmi/<id>.json`；当前工程写在 `active.txt`。原 FUXA SQLite 工程与 DAQ 保持原有存储。模拟设备及 Modbus 设备 ID 使用 `sh_<工程id>_<设备id>` 前缀，点位同理。切换工程时移除旧的受管设备，保留工程师自己创建的非 `sh_` 设备及其他高级配置，然后完整重启 Runtime。只修改布局不会重启通信。

由 SimpleHMI 管理的设备应在极简界面修改；下次变更设备配置或服务重启时，会按 SimpleHMI JSON 重新同步。不要依赖工程师编辑器中直接修改 `sh_` 设备的参数长期保留。一个服务实例只有一个当前工程，MVP 按单用户操作设计。

历史显示使用后台有限内存缓存，重启或修改设备配置后清空。受管 Tag 默认不启用持久 DAQ，以避开上游在高频设备重载时的归档生命周期冲突。长期历史、归档和查询底层仍保留在工程师体系中；极简界面暂未提供持久历史检索。

## 下一步接真实 Modbus TCP PLC

1. 在运行本项目的工控机/电脑上确认能访问 PLC 的 IP。准备 PLC 寄存器表、Unit ID、读写许可及数据类型。
2. 项目中 **设备 → 添加设备 → Modbus TCP**，填写名称、PLC IP、端口（通常 502）；展开高级设置填写 Unit ID、轮询周期和超时。
3. 点击测试连接。测试会先建立 TCP，再尝试读取 **保持寄存器地址 1**。如果 TCP 成功但该地址不合法，界面明确提示读取失败，仍可继续添加实际有效点位。
4. 添加变量。MVP 地址是 **1 起始的区内地址**，不是六位完整编号：保持寄存器偏移 0 → 区域“保持寄存器”、地址 `1`；常见 `40001` 通常对应同一位置，但必须以 PLC 文档确认。不能输入三菱 `D100` 或 Siemens `M0.0` 当作 Modbus 地址。
5. 类型选择 UInt16/Int16/Float32；Float32 占两个连续寄存器。默认大端。若设备要求其他字节/字序，请使用工程师原生设备设置，或下一版扩展映射；普通模式当前只实现上述类型。
6. 原始值 236 需要显示 23.6：设置倍率 10。单位填写 °C。Bool 必须选择线圈或离散输入区域。输入寄存器、离散输入为只读。
7. 先用数值组件绑定并测试读取，再为明确可写的点位开启允许写入，将按钮或开关绑定到它。
8. 运行模式点击按钮，程序要求驱动写入成功，并等待逐点时间戳更新后的回读值与目标相符。断线/拒绝/回读不符会显示失败。
9. 如需 RTU、S7、OPC UA，在工程师模式的插件页安装相应依赖后到设备页配置。极简模式保留了这些入口，但没有实现这些协议的简化向导，也没有做真机验收。

本次没有提供真实 PLC 地址，因此**验证到的是实际 TCP 协议测试从站，并非物理 PLC**。

## 工控机 / kiosk

- 编辑：`http://127.0.0.1:1881/simplehmi/`
- 运行预览：`http://127.0.0.1:1881/simplehmi/?runtime=1`
- 无工具栏运行：`http://127.0.0.1:1881/simplehmi/?runtime=1&kiosk=1`
- “全屏”使用浏览器 Fullscreen API；Esc 返回。操作系统级 kiosk 可用 Chromium 的 `--kiosk` 参数打开上述地址。

MVP 仅监听 loopback，本机使用；未接入极简模式登录、多用户角色和远程部署。启用 FUXA 安全模式后，极简 API 会拒绝请求，须使用原工程师登录路径，不会绕过已有安全设置。当前交付不作为远程生产控制系统发布。

## 连接编辑与布线修正

顶部“连接”或直接点击管线可修改起点、终点、端口、流向和 Bool 运行状态绑定。先看预览再保存；支持反向、删除、撤销和保存恢复。运行页隐藏编辑命中区域；状态为新鲜 true 时显示流动，false 停止，失效则显示为虚线未知状态。

同侧回流端口现在使用简洁外侧通道，不再为了最后一段方向制造额外折角。自动布局先识别有向循环再展开设备，回流走外侧，分支按上游关系排序。名称固定为单行，不挤压设备图形；完整名称可悬停查看。自动端口遇到名称或设备遮挡会选择其他端口并说明原因；明确指定的端口被遮挡时返回阻断诊断。交叉线用留白分隔，并说明交叉不代表连通；共线路径仍会提示需要调整，不声称所有大图交叉都已自动消除。

新增 8 项连接回归，并用独立 Chrome 完成实际页面操作。测试步骤见 [浏览器验收](integrations/browser/README.md)。所有测试工程均隔离；图形连接不自动定义物理仿真或 PLC 控制逻辑。
